# 朗读稿发音预检

所有 Radio、Reading、Weekly 提交前读取本页。展示文稿保留标准拼写；朗读适配放入 `audio_script`（Radio 可选，省略时读 script）。两版必须事实、数字、否定、归因一致，不能借“发音优化”改事实。

- 本地 VoxCPM 不提供经过验证的 SSML / phoneme 接口；Gemini 的人物性格通过独立 style 元数据由服务传递，不把舞台指令写进朗读稿。不要发送 `<phoneme>`、拼音括号或“请读作…”指令，它们可能被直接念出。
- 多音字以完整语义短语表达。核实“重新加载”“负载过重”“银行行长”等语境；只有原文语义确为重新加载时，才把“重载”改写为“重新加载”。不要全局替换“重”“行”“长”，不改人名地名为猜测的同音字。
- 英文品牌、产品、模型、项目、人名及有意义的技术名称，在展示稿和 `audio_script` 中都保留来源中的规范英文拼写，例如 OpenAI、Claude、Gemini、DeepSeek、VoxCPM、GitHub。禁止改成中文音译、谐音汉字、拼音或拆字，不得以“方便 TTS”为由只在朗读稿里偷换。中文释义可以在首次出现时简短补充，但不能替代英文名称。已有明确通行的中文语义译名可以按语境使用；不要自行创造译名。
- CPU、GPU、API、USB、AI、LLM 等有意义的缩写优先保留；需要帮助听众理解时，首次出现补充符合来源语境的中文释义，后续继续使用缩写。不要全局展开多义缩写，不拆 OpenAI 等名称，不把字母加空格当作发音修复。
- 提交前逐一对照来源、展示稿和朗读稿中的英文专名，确认没有变成中文音译。TTS 读音不佳时保留原词，使用引擎独立的风格控制或重新生成并抽听，不篡改名称。没有听验时如实记录，不能宣称已校准。
- 百分数、计量单位、公历年份、版本号、范围和公式在 `audio_script` 中要口语化：12.5%→百分之十二点五，3.5GHz→三点五吉赫兹，公历年份如 2026年/2027年/2028年 在 `audio_script` 中转写为“二零二六年/二零二七年/二零二八年”（防止云端/本地 TTS 文本前端将其按基数词误读为“两千零二十六年”），v1.3.32→一点三点三十二版（必要时按主版本、次版本、修订号分别说明，避免重复“三”被吞读）。负数、百分比与百分点严格区分。对 `≤`、`×`、`/`、`~`、货币和科学记数法逐处按含义转写，不做字符全局替换。C++/C# 等名称保留标准拼写，不替换为汉字音译。
- URL、脚注标记、Markdown、emoji 不进入朗读稿；保留其有价值的信息并用自然语言说清楚。
- 在私有运行目录记录 `pronunciation-review.md`：原表达→朗读表达→依据；没有改动则简记已检查。提交前对照两版，特别核对数字、单位、人名和否定词。
- 音频完成后，对本次新增/陌生人名、多音词、公式、混合中英文术语做重点抽听/转写比对。ASR 不是读音正确的充分证据，专名识别错误应结合实际试听判断。无音频听取能力时明确“发音尚未听验”，不能声称完全准确，也不要为纠音重复发布同一节目。
