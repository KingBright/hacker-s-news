# 朗读稿发音预检

所有 Radio、Reading、Weekly 提交前读取本页。展示文稿保留标准拼写；朗读适配放入 `audio_script`（Radio 可选，省略时读 script）。两版必须事实、数字、否定、归因一致，不能借“发音优化”改事实。

- 当前 VoxCPM 不提供经过验证的 SSML / phoneme 接口。不要发送 `<phoneme>`、拼音括号或“请读作…”指令，它们可能被直接念出。
- 多音字以完整语义短语表达。核实“重新加载”“负载过重”“银行行长”等语境；只有原文语义确为重新加载时，才把“重载”改写为“重新加载”。不要全局替换“重”“行”“长”，不改人名地名为猜测的同音字。
- 专用术语、专有名词先查原作者/官方介绍的拼写与读音。有可靠通行中文名可在朗读稿使用，展示文稿保留原名。无可靠读音时保留原名并在运行报告标记待抽听，不能自称已校准。
- 常见技术缩写优先使用已核实的规范中文全称：CPU→中央处理器，GPU→图形处理器，API→应用程序编程接口，USB→通用串行总线，AI→人工智能，LLM→大语言模型；Cortex 只自动展开 CPU/GPU/USB/HTTP/HTTPS/HTML。API 也可能指原料药，AI 可能指 Adobe Illustrator，LLM 也可能指法学硕士；这些多义缩写必须由你根据来源语境选择全称，不能全局展开。不要拆 OpenAI 等普通名称。SQL 等存在不同惯用读法的缩写按具体语境核实。字母之间加空格不等于读准，实际样本中 GPU/API 仍发生转写混淆，不把这种做法当可靠修复。
- 百分数、计量单位、版本号、范围和公式要口语化：12.5%→百分之十二点五，3.5GHz→三点五吉赫兹，v1.3.32→一点三点三十二版（必要时按主版本、次版本、修订号分别说明，避免重复“三”被吞读）。负数、百分比与百分点严格区分。对 `≤`、`×`、`/`、`~`、货币和科学记数法逐处按含义转写，不做字符全局替换。C++/C# 可写成“C 加加”/“C sharp”，必须保持所指语言不变。
- URL、脚注标记、Markdown、emoji 不进入朗读稿；保留其有价值的信息并用自然语言说清楚。
- 在私有运行目录记录 `pronunciation-review.md`：原表达→朗读表达→依据；没有改动则简记已检查。提交前对照两版，特别核对数字、单位、人名和否定词。
- 音频完成后，对本次新增/陌生人名、多音词、公式、混合中英文术语做重点抽听/转写比对。ASR 不是读音正确的充分证据，专名识别错误应结合实际试听判断。无音频听取能力时明确“发音尚未听验”，不能声称完全准确，也不要为纠音重复发布同一节目。
