## 根因

1. `curated_feed.rs` 的 LLM 失败兜底调用 `fallback_analysis_from_text`，将原文
   截断后套上“作者主张”“原文信息压缩”和听稿开场白，仍返回可发布的分析结果。
   这与当前样本的模板形态一致；未读取当时运行日志，不能断言每篇都由同一次故障造成。
2. 旧 `run_radio_episode_agent.py` 仍调用本地 LLM，旧 Reading 脚本默认日期固定，
   “外部调度脚本”没有实质变成成熟 agent 的编辑过程。
3. 旧 `enabled=false` 同时停掉采集，外部 agent 缺少可靠统一的素材入口。
4. 旧提交路径的校验错误会终结租约，多个发布写入不在同一事务，存在半成品风险。
5. 原始媒体没有形成“可检查素材 → 观察证据 → 听稿描述 → 原图/原音链接”的明确约定。

## 本轮改进

- 显式 `external_agent` 模式持续采集缓存，核心内容理解交给当前成熟 agent；
  保留默认自驱模式，不改变旧模式的兜底策略以免悄然改变稳定生产行为。
- 外驱内容需包含来源事实记录、去重检查和中文编辑审核；Nexus 拒绝明显英文复制、
  标记残留与空稿。该门槛是必要条件，不能自动证明模型的事实判断正确。
- 保留 RSS/Atom enclosure、HTML 媒体 URL、原始 HTML、缓存 hash 与时间；媒体必须
  如实标记 inspected / transcript_only / unavailable。
- 保持原图及音视频来源可达，网页支持正文音频控件；修复 Android 正文链接看似可点
  实则无点击行为的问题。网页与 Android 忽略无内容的引用标记，避免显示孤立的 `> >`。
- 编辑完成、音频排队、音频完成分别汇报；同稿重提不重复发布，异常回滚后可修正。

## 新稿对照与验收标准

以 Quoting voxium 为例，新稿约 500 中文字符。先说明是被转载的个人陈述，再归纳
“生成更多材料”和“理解、验证并交付”的区别，明确没有独立核验和公司回应，不能
推导为行业普遍结论。不把作者抱怨包装成实证研究。

样稿仅用于隔离验收：线上已存在相同原文 URL，不应作为新内容重复发布。
源页：[Simon Willison 引文](https://simonwillison.net/2026/Sep/20/voxium/)。

后续真实批次逐项人工/agent 复核：来源忠实度、选题新信息、中文可听性、结构压缩、
媒体处理各 0–2 分，至少 8/10 且来源忠实度不能为 0；连续运行记录重复率、抓取失败率、
稿件退回原因、音频完成率和媒体不可用比例，再判断是否达到生产稳定性。单次测试
通过不等于长期稳定，不能把编译通过或排队成功当成听觉验收。
